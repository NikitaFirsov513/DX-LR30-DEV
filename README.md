# PJ26 / DX-LR30-900M22S — C11, CMSIS, CMake, EIDE

Проект для PJ26 с MCU STM32F103C8T6, Flash 64 КиБ и SRAM 20 КиБ. Команды ниже выполняются из корня репозитория. STM32 настраивается вручную через CMSIS. Приложение работает без RTOS, радио использует отдельный драйвер Semtech. CubeMX нужен для визуального просмотра пинов и базовых настроек.

Базовая CMSIS-версия `V-0.1.0` проверена пользователем на двух платах: обмен в обе стороны и восстановление после перезапуска. Текущие изменения CRC/диагностики требуют отдельной проверки на платах. План повторной проверки находится в [docs/VALIDATION.md](docs/VALIDATION.md). Старый Radio HEX локально сохранён в `reference/hal-radio.hex`; резервные бинарные файлы не входят в Git.

## Что открыть и как собрать

Открыть `dx_lr30_pj26.code-workspace` в VS Code. При переносе проект уже был переоткрыт, и EIDE принял новые каталоги. При будущей регенерации `.eide/eide.yml` сначала закрыть workspace PJ26: активный EIDE может восстановить старую конфигурацию из кэша.

**Через EIDE:** выбрать Radio или UART, нажать Build, затем Flash. Автоопределение CH340/CH341 и оформление консоли сохранены. EIDE собирает в `build/eide/<target>`, а кнопка Flash получает HEX активного target.

**Через терминал или агента:**

```powershell
python tools/build.py --target Radio
python tools/build.py --target UART
python tools/test.py
```

Эти команды используют CMake/Ninja и не зависят от того, как EIDE перезаписал свой YAML. Нужен Python 3.10+ в PATH. Путь к другому интерпретатору для задач VS Code можно задать параметром `pj26.python` в локальном `.vscode/settings.json`, скопировав `.vscode/settings.example.json`. Этот локальный файл игнорируется Git; общие задачи и настройки остаются в репозитории.

В **Terminal → Run Task** доступны `Build Radio`, `Build UART`, `Flash Radio`, `Flash UART`, `Check project`, `List boards` и предпросмотр консоли. Задачи Flash сначала выполняют соответствующую сборку CMake. Ctrl+Shift+B по умолчанию собирает Radio.

| Система сборки | Radio HEX | UART HEX |
|---|---|---|
| CMake / задачи VS Code | `build/Radio/dx_lr30_pj26.hex` | `build/UART/dx_lr30_pj26.hex` |
| Кнопки EIDE | `build/eide/Radio/dx_lr30_pj26.hex` | `build/eide/UART/dx_lr30_pj26.hex` |

Выходные каталоги разделены: две системы не перезаписывают результаты друг друга. Обе используют те же исходники, подключения и определения из `project.json`; CMake читает его напрямую, конфигурация EIDE создаётся `python tools/sync_eide.py`. Эту команду нужно повторять после изменения списка каталогов/include/defines в manifest: закрыть workspace, выполнить команду во внешнем терминале и открыть workspace снова. Для обычных изменений C-кода и параметров в заголовках регенерация не нужна. EIDE может сохранять файл в YAML — терминальной сборке это не мешает.

## Прошивка через USB-C

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/flash.ps1 -Firmware build/Radio/dx_lr30_pj26.hex
```

1. Закрыть HTerm/MCUISP/CubeProgrammer, если они держат COM-порт.
2. Запустить Flash. `AUTO` выбирает единственный подходящий CH340/CH341; при двух платах указать `-OverridePort COMx`.
3. Если появилось жёлтое приглашение RST, один раз нажать и отпустить RST на плате.
4. Дождаться записи, проверки чтением и запуска.

Копии Flash сохраняются в `build/backups`, журналы — в `build/flash-logs`. Настройки ISP находятся в `tools/flash-settings.json`. Старый аргумент `-Port COM5` не переопределяет автоопределение. Подробности и безопасные команды проверки — в [AUTOFLASH.md](AUTOFLASH.md).

Режим **UART** возвращает принятые байты в тот же COM-порт. Режим **Radio** передаёт UART-пакеты через радио и выводит принятые радиопакеты в UART. Один Radio HEX используется на обеих платах. Терминал: **9600 8N1**, local echo выключен.

## Где изменять

| Файл | Назначение |
|---|---|
| `board/pins.def` | Сигналы платы, порты/пины, режимы и начальные уровни |
| `board/config.h` | Кварц, частоты шин, UART baud, пауза пакетирования, тайм-ауты |
| `mcu/clock.c` | Ручная последовательность настройки RCC/Flash/SysTick |
| `mcu/gpio.c`, `spi.c`, `uart.c`, `timer.c`, `exti.c` | Реализации на регистрах STM32 |
| `devices/sx126x/radio_config.h` | Частота, SF/BW/CR, преамбула, мощность и CRC |
| `devices/sx126x/radio.c` | Состояния радио, отправка, приём и обработка ошибок |
| `devices/sx126x/sx126x_port.c` | Реализация интерфейса Semtech через SPI/GPIO платы |
| `app/serial_frames.c` | Пакетирование UART и ограниченная очередь |
| `app/diagnostics.c` | Дребезг кнопки KEY и форматирование локальной статистики |
| `app/main.c` | Соединение модулей и основной цикл |

Радиопараметры: **868,100 МГц, SF9, BW125, CR4/6, preamble 8, explicit header, CRC on, +10 dBm**. В отличие от `V-0.1.0`, CRC теперь обязателен: прошить обе платы одним новым Radio HEX. Принятые пакеты без CRC отбрасываются. Максимальный пакет 255 байт, разделитель UART-пакетов — пауза 5 мс. Адреса, ACK, повторы и mesh не добавлены.

`board/config.h` описывает фиксированное дерево тактирования. Для изменения частоты недостаточно поменять число в заголовке: необходимо поправить последовательность `clock.c`, параметры Flash, делители шин/таймеров и справочный `.ioc`. Компиляционные проверки предотвращают часть таких рассогласований.

## Диагностика радиоканала

В HTerm на **9600 8N1** нажать и отпустить физическую кнопку **KEY** на плате (PB12, не RST). Локальный отчёт `[diag]` покажет начатые/завершённые передачи, принятые пакеты и байты, ошибки CRC/заголовка, пакеты без CRC, тайм-ауты, watchdog, ошибки UART и потери очереди. RSSI/SNR относятся к последнему принятому корректному пакету; до первого пакета выводится `N/A`.

Отчёт не отправляется по радио. При удержании кнопки он не повторяется; нажатие во время TX откладывается до возврата в RX. При фатальной ошибке делается одна попытка вывести такой же снимок. Печать использует тот же UART и на несколько сотен миллисекунд занимает основной цикл — снимать показания лучше между сериями сообщений. Счётчики живут до сброса MCU. Периодических строк и специальных UART-команд нет, данные, включая двоичные, передаются как прежде.

Значение `tx_done` подтверждает завершение локальной передачи, без ACK оно не доказывает доставку. Счётчики CRC не показывают пакеты, которые приёмник вовсе не обнаружил. Расшифровка полей и процедура проверки: [docs/RADIO_DIAGNOSTICS.md](docs/RADIO_DIAGNOSTICS.md).

## CubeMX

Открыть `cubemx/dx_lr30_pj26.ioc`. Он отражает подключения платы и базовые параметры, но **не входит в сборку и не генерирует рабочую инициализацию**. Изменение MX само по себе не меняет прошивку. Рабочее назначение пинов — в `board/pins.def`.

После изменения подключений обновить справочный `.ioc` и экспорт `cubemx/pinout.csv`; `python tools/verify.py` проверяет соответствие. Код MX для экспериментов генерировать в отдельную папку. Таймеры, приоритеты IRQ и логика радио описаны в коде и [архитектуре](docs/ARCHITECTURE.md), а не полностью в MX.

## Зависимости и воспроизводимость

Нужны Python 3.10+, CMake 3.24+, Ninja и Arm GNU Toolchain. Компилятор и инструменты можно установить отдельно или использовать уже установленные EIDE/STM32CubeIDE. Порядок поиска: явный `--gcc-dir` для GCC, переменные окружения, локальный `tools/local-settings.json`, затем PATH. Для GCC также проверяется стандартный каталог EIDE в домашнем каталоге пользователя.

Для нестандартных расположений скопировать `tools/local-settings.example.json` в `tools/local-settings.json` и заполнить нужные пути. Пустые поля используют обычный поиск. Локальный файл игнорируется Git. Альтернатива — переменные окружения:

```powershell
$env:ARM_GCC_DIR = 'C:/Tools/arm-gnu/bin'
$env:NINJA_EXE = 'C:/Tools/ninja/ninja.exe'
$env:CMAKE_EXE = 'C:/Program Files/CMake/bin/cmake.exe'
python tools/build.py --target Radio
```

Можно использовать стандартные presets: `cmake --preset radio`, `cmake --build --preset radio`; для этого GCC/Ninja должны быть доступны через переменные окружения/PATH. Генератор исходников в сборке не используется, сетевых загрузок при сборке нет.

`toolchain.lock.json` фиксирует проверенное окружение, `vendor/lock.json` — SHA256 сторонних исходников, а каждый CMake build сохраняет фактическую версию компилятора в `build/<target>/build-info.json`. Нативные C-тесты на Windows используют установленные MSVC/Windows SDK; на Linux можно использовать системный C-компилятор.

## Проверка, отладка и документация

`python tools/test.py` — общий набор проверок без подключения к плате. Отдельно: `python tools/verify.py` для распиновки и готовых ELF/HEX/BIN.

С одним USB-C доступны загрузчик UART, журналы и тесты обмена. Для пошаговой отладки нужен SWD-адаптер. Подготовлен профиль Cortex-Debug `Radio: SWD / ST-LINK (optional)` и SVD в `debug/`. Он требует ST-LINK, OpenOCD и подключения к SWD; этот профиль не проверен с физическим отладчиком. Параметры инструментов — `pj26.armGccDir` и `pj26.openocd` в workspace. Общая SVD описывает семейство: наличие регистра в просмотрщике не доказывает наличие периферии в корпусе C8.

Локальные руководства и происхождение файлов: **[docs/README.md](docs/README.md)**. Устройство проекта: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Проверки на компьютере и план стенда: [docs/VALIDATION.md](docs/VALIDATION.md). Правила для агента: [AGENTS.md](AGENTS.md).

Предыдущая структура сохранена в резервной копии, предыдущая прошивка — в `reference/`. Сведения об исходном варианте находятся в `reference/BASELINE.md`.

## Что входит в Git

В репозитории хранятся исходники `app/`, `board/`, `mcu/`, `devices/`, фиксированные зависимости `vendor/` с лицензиями, `tools/`, `tests/`, настройки CMake/EIDE/VS Code, справочный CubeMX и SVD, наши Markdown-инструкции и списки источников/версий документации.

Локально остаются скачанные PDF, офлайн-сайт `docs/cmsis/`, машинный журнал `docs/local-manifest.json`, содержимое `build/`, резервные HEX/BIN/ZIP в `reference/` и файлы личных настроек. Они исключены через `.gitignore` и сохраняются на диске.

Для сборки свежего клона PDF и резервные копии не требуются. Для загрузки документации см. [docs/README.md](docs/README.md). Готовые HEX/BIN конкретного выпуска можно распространять отдельно от исходников.
