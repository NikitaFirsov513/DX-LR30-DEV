# DX-LR30-900M22S на PJ26 для CubeMX и EIDE

Адаптация заводского UART ↔ LoRa demo под STM32F103C8T6, GCC и EIDE. 5 ноября 2026 пользователь подтвердил запуск UART-теста и передачу сообщения между двумя платами по LoRa. Дальность, потери пакетов и длительная стабильность пока не измерялись.

## Что открыть

- `dx_lr30_pj26.code-workspace` — открыть в VS Code с EIDE. Два target: `UART` для проверки COM-порта и `Radio` для радиообмена.
- `cubemx/dx_lr30_pj26.ioc` — открыть в STM32CubeMX для просмотра выводов и тактирования. Файл проверен загрузкой/сохранением в установленном CubeMX 6.16.1; `cubemx/pinout.csv` экспортирован самим CubeMX.
- `build/UART/dx_lr30_pj26.hex` и `build/Radio/dx_lr30_pj26.hex` — готовые результаты локальной GCC-сборки, если ещё не очищена папка build.

CubeMX здесь служит отдельным проектом для сверки назначения выводов. Его сгенерированные файлы не входят в EIDE-сборку. Изменения `.ioc` нужно переносить в соответствующие драйверы вручную. Генерировать код для сравнения следует только в отдельную папку `cubemx`; не выбирать корень этого EIDE-проекта.

## Где изменять код

Для рабочего радиообмена выбрать target **Radio**, затем выполнить Build. Target UART оставлен для отдельной проверки эха последовательного порта.

| Файл | Что изменять |
|---|---|
| `Main/main.c` | Запуск периферии, скорость `UsartInit(9600)`, основной цикл |
| `LR_driver/UserConfig.h` | Частота `LORA_FRE`, назначение выводов и размер пакета |
| `LR_driver/UserConfig.c` | `LoraInit`: SF, BW, CR, мощность; `Data_Processing`: отправка; `OnRxDone`: обработка принятого пакета |
| `LR_driver/src/sx126x_hal.c` | Обмен по SPI, сброс радио и ожидание BUSY |
| `Driver/` | Драйверы UART, SPI, таймеров и прерывания DIO1 |

После изменения радиопараметров обе платы должны использовать совместимые настройки. Текущие исходники соответствуют проверенному Radio HEX; контрольные суммы исходников и эталонного HEX включены в архив поставки.

## Подключение радио по документации семейства

| Сигнал | STM32 | Режим |
|---|---|---|
| NSS | PA4 | GPIO output, исходно HIGH |
| SCK | PA5 | SPI1 |
| MISO | PA6 | SPI1 input |
| MOSI | PA7 | SPI1 |
| NRST радио | PA3 | GPIO output, исходно HIGH |
| BUSY | PA2 | GPIO input |
| DIO1 | PC15 | EXTI15, rising edge |
| RXEN | PA1 | GPIO output |
| TXEN | PA0 | GPIO output |
| UART TX | PA9 | USART1_TX |
| UART RX | PA10 | USART1_RX |
| DIO2 | нет назначения MCU | В заводской схеме отдельная сеть только у вывода 8 радиомодуля |
| DIO3 | нет назначения MCU | В заводском демо не используется |

Для съёмной LR30-A наличие DIO2 на разъёме не подтверждает соединение с STM32. Перед радиоиспытаниями прозвонить NSS/SCK/MISO/MOSI/NRST/BUSY/DIO1/TXEN/RXEN на своей PJ26. PC15 занят DIO1: LSE не включать. Маркировка радиомодуля 900M22S не определяет точную модель установленного MCU; сборка рассчитана на C8, 64 КиБ Flash и 20 КиБ SRAM.

## Настройки демо

- HSE 8 МГц, PLL ×9, SYSCLK 72 МГц, APB1 36 МГц, APB2 72 МГц.
- UART1: **9600, 8N1**, без flow control. USB-C используется через USB–UART мост платы; USB Device/CDC в MCU не требуется.
- SPI1: mode 0, MSB first, 8 bit, software NSS, 4,5 МГц.
- Radio: **868,100 МГц**, SF9, BW125, CR4/6, преамбула 8, без CRC, мощность **+10 dBm**. Оба экземпляра должны иметь одинаковые параметры. Изменять в `LR_driver/UserConfig.h` / `LR_driver/UserConfig.c` и пересобирать.
- Данные UART объединяются по паузе около 5 мс либо по размеру 255 байт. Это короткое демонстрационное соединение без ACK, повторов, адресации и mesh.

## Первый запуск с одним USB-C

1. Открыть workspace, выбрать target **UART**, выполнить Build. Этот target не инициализирует радио и возвращает введённые байты в тот же COM-порт.
2. Закрыть терминал, чтобы он освободил COM. Открыть MCUISP из пакета производителя. Для **PJ26** выбрать `STM ISP`, верный COM и `Reset@DTR High(>+3V), ISP@RTS Low`.
3. Выполнить `Read ChipInfo`, затем нажать RST. Убедиться, что MCU отвечает и соответствует проекту. В инструкции производителя скорость MCUISP — 460800; она независима от скорости приложения 9600.
4. Выбрать HEX именно выбранного target, включить `Verify` и `Run After ISP complete`, выполнить `Start ISP`.
5. Закрыть MCUISP, открыть COM на 9600 8N1, нажать RST. Ожидается `PJ26 GCC...`, затем `UART_ONLY: echo test...`. Ввод текста должен возвращаться с платы; local echo терминала выключить.
6. После проверки распиновки собрать/записать **Radio** в две платы. Открыть оба COM-порта на 9600 и проверить передачу короткого текста в обе стороны. В этом режиме один и тот же HEX устанавливается в обе платы.

EIDE Flash вызывает tools/flash.ps1: скрипт сам подключается по UART, сохраняет копию Flash, записывает HEX, проверяет чтением и запускает приложение. MCUISP не открывается. Порт определяется автоматически по USB VID/PID CH340/CH341; в tools/flash-settings.json установлен AUTO. Bluetooth исключён. При нескольких платах требуется явный выбор. Если нет ACK после автоматического сброса, нажать физический RST по приглашению. Запись и проверка на COM7 подтверждены 5 ноября 2026. Подробности: AUTOFLASH.md. После обновления один раз выполнить Developer: Reload Window в VS Code.

Документация производителя по версиям PJ23/PJ26: https://github.com/DX-SMART/LoRaModule/blob/main/Troubleshooting%20Guide.md

## Сборка без интерфейса EIDE

Из папки проекта при наличии Python 3:

```powershell
python tools/build.py --target UART
python tools/build.py --target Radio
```

По умолчанию используется `%USERPROFILE%/.eide/tools/gcc_arm/bin`. Другой путь передать через `--gcc-dir`. Скрипт использует те же исходники, defines и include directories из `.eide/eide.yml`. Он не подключается к плате.

## Что изменено относительно заводского пакета

- STM32F103xE, ARMCC startup и разметка 512/64 КиБ заменены на STM32F103xB, GNU startup и разметку C8 64/20 КиБ. Добавлены недостающие GCC/C8 CMSIS-заголовки из установленного STM32Cube FW_F1 V1.8.7.
- Исправлено тактирование GPIOC для DIO1, включён AFIO; SPI снижен с 18 до 4,5 МГц, MISO задан входом.
- Вывод `printf` перенесён на GCC/newlib; добавлен UART-only target.
- SPI-обработка прерывания радио перенесена из EXTI callback в основной цикл; флаг сделан volatile.
- Приём радио выводится с явной длиной, без чтения за концом payload. Очередь UART заменена ограниченной кольцевой очередью с атомарным потреблением относительно IRQ.
- Ожидание BUSY ограничено 1 секундой с диагностикой в UART; перед аппаратным сбросом радио BUSY не ожидается.

Исходный пакет DX-SMART на диске D: не изменялся. Исходники ST и Semtech сохраняют свои уведомления об авторстве и лицензировании. Эта адаптация — материал для стенда, не испытанная прошивка изделия.
