# PJ26 development contract

Read README.md, docs/ARCHITECTURE.md and docs/VALIDATION.md before changing firmware.
Use the repository containing this file as the project root. Do not modify other copies.

## Hardware and ownership

- MCU: STM32F103C8T6, 64 KiB Flash, 20 KiB SRAM, HSE 8 MHz, core 72 MHz.
- board/pins.def is the compiled pin map; board/config.h describes board clocks and UART settings.
- mcu/ owns STM32 registers and IRQ handlers. Use CMSIS; no STM32 HAL initialization or handles.
- app/ owns UART framing and application flow. devices/sx126x/ owns the radio state machine and Semtech transport port.
- vendor/ is a pinned dependency snapshot. Preserve licenses and document intentional changes in vendor/README.md; update vendor/lock.json hashes only after reviewing the changes.
- CubeMX .ioc is a reference view. It does not configure the firmware. Keep it and pinout.csv consistent when changing pin assignments; run tools/verify.py.
- DIO1 is PC15, EXTI15. Do not enable LSE. DIO2 has no confirmed MCU connection.
- AFIO uses default SPI1/USART1 mapping, JTAG is disabled, SWD PA13/PA14 is retained.

## Implementation rules

- One owner for each peripheral. Do not initialize it twice or patch configuration from app/main.c.
- ISR callbacks only capture data/events. Never run SPI radio commands, printf, delays or blocking UART TX in interrupts.
- Restore the saved PRIMASK after critical sections; never blindly enable interrupts.
- Bound hardware waits and propagate transport errors. Use unsigned elapsed-time subtraction for tick wraparound.
- Keep the existing air interface unless the user requests a change: 868.1 MHz, SF9, BW125, CR4/6, preamble 8, explicit header, CRC off, IQ normal, +10 dBm.
- No unsolicited ACK, addressing, RTOS, frequency or transmit-power changes.
- Consult local RM0008, datasheet and errata before changing register sequences. Documentation index: docs/README.md. Archived versions are identified there.

## Build and validation

Use Python 3.10+. Machine-specific paths belong in ignored tools/local-settings.json (build tools) and .vscode/settings.json (editor/task settings), not in shared configuration. Environment variables override local build settings; PATH and the standard EIDE GCC location are fallbacks.

```text
python tools/build.py --target Radio
python tools/build.py --target UART
python tools/test.py
```

tools/test.py builds both variants, validates memory/vector tables and pin-map consistency, executes production C framing/radio code with simulated I/O, and tests the Windows ISP/port selector. It never opens a COM port.
EIDE configuration is generated by python tools/sync_eide.py from project.json. Close the PJ26 workspace before regenerating it, then reopen it: an active EIDE instance can overwrite external changes with its cached configuration. CMake does not parse EIDE's mutable YAML. Do not edit only the generated EIDE source/define lists.
CMake artifacts are build/Radio and build/UART. EIDE artifacts are build/eide/Radio and build/eide/UART, preventing collisions between build systems.

## Hardware operations and reporting

Keep settings in tools/flash-settings.json; AUTO selects a unique CH340/CH341 and excludes Bluetooth. Respect explicit -OverridePort.
Flashing can reset the board and replace firmware. Perform it when requested or already authorized in the conversation. A software refactor does not by itself prove radio communication on hardware.
Report exactly which checks ran. Do not label this CMSIS revision hardware-verified based on the old HAL demo's successful test.
Keep the original source/archive and reference/hal-radio.hex available for recovery. Never modify option bytes or protection as a routine fix.

## Repository contents

Commit source code, vendor snapshots/licenses, build/flash tools, tests, shared editor configuration, Markdown documentation and source/version manifests.
Downloaded PDFs, docs/cmsis, docs/local-manifest.json, build output, recovery binaries/archives and machine-specific settings stay local and are ignored by Git. Do not delete them while preparing a commit.
A fresh checkout must build and pass software checks without PDFs, offline HTML, reference binaries or local settings when the required tools are on PATH or supplied through environment variables. Keep *.example.json templates portable.
