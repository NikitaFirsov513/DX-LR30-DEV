# Автоматический тест связи двух PJ26

Тест запускается на Windows-ПК, к которому одновременно подключены две платы PJ26 через USB-C. На обеих должна работать Radio-прошивка. Для текущего адресного варианта обе платы нужно обновить одним новым Radio HEX. Дополнительные Python-пакеты не нужны: используется Windows PowerShell 5.1/.NET из Windows. Тест использует адресный PN/v1 канал, не выполняет ISP-команды. Перед серией читает ID/MTU, проверяет приём-и-отбрасывание одного пакета на чужой адрес и временно задаёт адреса A↔B. В finally пытается вернуть исходные назначения; при прерывании/обрыве они могут остаться изменёнными, RST возвращает broadcast. Подробности — [ADDRESSED_PROTOCOL.md](ADDRESSED_PROTOCOL.md).

## Быстрый запуск из VS Code

1. Подключить обе платы, закрыть HTerm, MCUISP, CubeProgrammer и другие программы, удерживающие их COM-порты.
2. Нажать **F1**, выбрать **Tasks: Run Task**, затем **Test radio link**.
3. В консоли появится соответствие **A = COMx, B = COMy**, затем результаты A→B и B→A. Автовыбор принимает ровно две платы CH340/CH341 по известным VID/PID, Bluetooth исключён.
4. Дождаться итогов. По умолчанию отправляется **20 пакетов по 64 байта в каждую сторону**, последовательно. Между передачами — пауза 200 мс; тайм-аут доставки — 4000 мс. При потерях серия занимает больше времени.
5. Результаты находятся в `build/link-tests`: JSON со сводкой/параметрами и CSV с каждой отправкой. Папка игнорируется Git. **Ctrl+C** останавливает тест и освобождает порты; при обычной остановке сохраняется частичный отчёт. При принудительном закрытии процесса может остаться только последний JSON checkpoint (`Completed=false`).

Если устройств больше двух, выбрать задачу **Test radio link: choose ports** и ввести порты A/B в появившихся полях. Она также полезна, если нужно явно сопоставить A/B с платами на столе. Список устройств показывает существующая задача **List boards**. Автотест всегда проверяет обе стороны, поэтому порядок A/B не влияет на полноту проверки.

Посмотреть оформление без подключения плат: **Test radio link preview**. Этот режим ничего не открывает и помечает отчёт `Mode=preview`. Его цифры синтетические и не подтверждают радиосвязь.

## Запуск из терминала

Из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test-link.ps1
```

Явные порты и длинная серия (номера ниже — пример, выбрать свои из List boards):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test-link.ps1 -PortA COM7 -PortB COM6 -Count 100 -Size 234
```

Настраиваются `-Count` (1..10000 в каждую сторону), `-Size` (24..234 байт для реальных адресных плат; до 255 в PC preview), `-TimeoutMs` (1000..60000), `-GapMs` (100..60000). UART — 9600 8N1, как в текущей прошивке. Минимум 24 байта нужен для служебных полей тестового payload и CRC32. Один `-Size` включает все эти поля, а не только данные шаблона. Длинные пакеты передаются дольше; слишком короткий тайм-аут создаст отметки опоздания даже при исправном канале.

Перед основной серией проверяется **чужой адрес**: отсутствие UART payload считается правильным только при увеличении foreign-счётчика получателя и совпадении source/destination/sequence в его последнем отклонённом заголовке. Если пробный пакет потерялся по радио, эта проверка завершается ошибкой, а не ложным PASS. Пробный пакет не входит в Sent/Received основной серии. JSON содержит исходные NodeA/NodeB и объект Addressing. Старый Radio без PN/v1 INFO не поддерживается этим тестом: обновить обе платы.

## Что измеряется

Внутри пользовательского payload находятся сигнатура, случайный ID сеанса, направление, номер, двоичный шаблон и CRC32. Эта PC-разметка не меняет формат прошивки. Приёмник на ПК восстанавливает кадры из произвольных порций serial-данных и сверяет каждый байт с ожидаемым. Пакеты другого сеанса, дубли, локальное UART-эхо и искажения не подменяют корректную доставку. Наличие данных только на отправляющем COM-порту не считается успехом.

Тест выполняет сначала серию A→B, затем B→A. В эфире не создаются ACK, автоматические повторы или одновременные передачи. Перед первой отправкой есть 1500 мс на запуск/очистку стартового serial-вывода; после последней попытки — ещё 1000 мс для учёта запоздавших кадров. Повторная прошивка не выполняется. При открытии портов используются уровни приложения `DTR=!resetDtr`, `RTS=!bootRts` из `flash-settings.json`, без последовательности входа в ISP или импульса сброса. Если платы оставлены в загрузчике, сначала запустить Radio обычным способом.

| Показатель | Смысл |
|---|---|
| Отправлено / `Sent` | Успешные записи тестовых кадров в COM отправителя; запись в COM ещё не доказывает отправку по радио |
| Получено / `Received` | Уникальные полностью совпавшие кадры на противоположном COM, включая пришедшие с опозданием |
| Потери / `Lost`, `LossPercent` | Отправлено минус получено на момент завершения теста |
| Опоздали / `Late` | Получены позже `TimeoutMs`; входят в Received, но серия не получает PASS |
| Дубли / `Duplicates` | Повторные корректные кадры того же сеанса/номера; не увеличивают Received |
| Эхо / `Echoes` | Тестовый кадр появился на отправляющем COM; возможен UART-only target или петля |
| Искажения / `Mismatches` | Совпали сеанс/номер и CRC32, но байты не совпали с отправленными |
| Ошибки кадров / `BadTestFrames` | На ПК обнаружены кадры с неверным CRC32; это **не** аппаратный счётчик CRC_ERROR радиочипа |
| Посторонние / `ForeignFrames` | Кадры PC-теста другого сеанса, направления или неотправленного номера |
| Задержка / `LatencyMs` | От записи на ПК до полного приёма на ПК, включая оба USB/UART, очередь, эфир и планирование Windows |

JSON содержит ID сеанса, UTC-время, режим, порты, параметры, сводку и все отправки. CSV содержит направление, номер, статус (`ok`, `timeout`, `late`, либо `waiting` у незавершённой попытки) и задержку. Номер уникален в пределах направления и сеанса. Прерванный тест никогда не получает `Passed=true`.

Код завершения: `0` — успешная серия либо успешный явно обозначенный preview; `1` — ошибка запуска/порта/файла; `2` — потери, опоздания или другие отклонения. Все кадры должны прийти вовремя, без дублей, эха, искажений и посторонних тестовых кадров, чтобы получить аппаратный PASS.

## Как проводить измерение

Не нажимать KEY и не отправлять другой UART-трафик во время серии: диагностический текст и занятый печатью MCU повлияют на результат. Сначала закончить тест, затем открыть HTerm и снять RSSI/SNR кнопкой KEY. Скрипт не считывает RSSI/SNR автоматически.

Измеряется доставка PC-кадров через весь тракт; UART может разделить payload на несколько радиопакетов при паузах между байтами. Потери или задержки могут возникать на ПК/USB/UART/в очереди/в эфире, поэтому число потерь здесь не следует считать чистым RF PER. Также здесь не измеряются максимальная пропускная способность, ACK/повторы, коллизии или маршрутизация между несколькими узлами. Для сравнения расстояний сохранять одинаковые параметры, расположение антенн и условия теста.

## Программные проверки

`powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test-link-host.ps1` проверяет настоящие parser/session алгоритмы в памяти без COM. Модели покрывают CRC32, бинарные размеры 24/64/255, дробление/склейку и восстановление потока, обе стороны, потери, эхо, дубли, опоздания, чужие сеансы, искажения, стартовую паузу и ошибки транспорта. Проверка пары устройств входит в `test-serial-ports.ps1`. Оба теста вызываются общим `python tools/test.py`. Preview дополнительно проверяет консоль и сохранение JSON/CSV, но не драйвер USB или эфир.
