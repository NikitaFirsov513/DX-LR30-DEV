# Проверки и границы подтверждения

## Программные проверки

`python tools/test.py` выполняет:

1. Сборку Radio и UART через CMake/Ninja/Arm GCC с `-Wall -Wextra -Werror`.
2. Проверку HEX: контрольные суммы, границы 64 КиБ, совпадение BIN/HEX, стек 20 КиБ SRAM, запас heap/stack, таблица векторов и отсутствие STM32 HAL в линковке.
3. Сверку таблицы `board/pins.def` с `.ioc` и экспортом `pinout.csv`, включая начальные уровни выходов и опорные настройки UART/SPI/clock.
4. Выполнение C-кода UART framing на компьютере: двоичные байты, размер 255/256, сброс по тишине, 5000 циклов перехода через границу очереди, переполнение и сброс повреждённого пакета.
5. Выполнение настоящего `radio.c` вместе с драйвером Semtech и моделью SPI-команд: параметры модуляции/частоты, RX/TX, бинарный payload, отложенная обработка IRQ, обязательный CRC в настройках TX/RX, отбрасывание CRC-off пакетов, ошибки CRC/заголовка, счётчики TX/RX/байтов, RSSI/SNR, timeout, watchdog с переполнением счётчика времени, ошибка транспорта и повторная инициализация.
6. Подавление дребезга KEY, один отчёт при удержании, отложенный запрос во время TX, переполнение времени, `N/A`/знаковые RSSI/SNR и вместимость отчёта при максимальных счётчиках.
7. Тесты ISP-парсера/протокола и автоопределения COM с моделями устройств, включая выбор ровно двух плат для link test.
8. Адресный C-слой: wire format/MTU, unicast/broadcast/foreign/self, дубли/session/TTL/переполнения, локальные команды/RAW, UART 255→234+21.
9. PC link test в памяти: CRC32, двоичные кадры/ресинхронизация потока, проверка обоих направлений, потери/искажения/дубли/эхо/опоздания/чужие сеансы, задержки и ошибки транспорта; node INFO correlation/version и доказательство foreign rejection по счётчику и метаданным, исключающее ложный успех при RF-потере.

Тесты не открывают COM-порт и не меняют память платы. Модели не подтверждают электрические подключения, точность задержек, работу кварца или радиодальность.

## Повторная проверка на платах после перехода на CMSIS

1. Собрать UART и прошить одну плату. На 9600 8N1 проверить стартовую строку `PJ26 CMSIS`, затем двоичное эхо, короткий текст и пакет длиной больше 255 байт. Local echo терминала выключить.
2. Собрать Radio. Прошить обе платы одним HEX, проверить стартовую строку `Radio ready` и передачу в обе стороны.
3. Проверить сообщения разной длины: короткое, затем длинное, затем снова короткое. Убедиться, что после короткой передачи принимается пакет большей длины.
4. Проверить серию сообщений с достаточным интервалом для выбранного LoRa airtime. Для оценки потерь использовать номера пакетов и сравнение исходных байтов на ПК.
5. Перезапустить питание обеих плат и повторить двусторонний обмен.
6. При наличии анализатора проверить NSS/SCK/MISO/MOSI, PA3 reset, PA2 BUSY, PC15 DIO1 и RXEN/TXEN. При SWD проверить SystemCoreClock, NVIC и причины fault.

Старая HAL-прошивка подтверждена пользователем 5 ноября 2026. Затем пользователь подтвердил базовую CMSIS-версию `V-0.1.0` (commit `7d24a25`): обмен на двух платах в обе стороны и восстановление после перезапуска. Эта запись основана на сообщениях пользователя в чате 6 ноября 2026; SHA256 фактически прошитого HEX и отдельный стендовый журнал не предоставлены. Успех базовой версии не подтверждает новые CRC/диагностику. После реального теста записать дату, target, SHA256 HEX, параметры UART/LoRa и результат сюда либо в отдельный стендовый журнал.

## Проверка новых CRC и диагностики

Порядок действий, ожидаемые счётчики и ограничения измерения потерь находятся в [RADIO_DIAGNOSTICS.md](RADIO_DIAGNOSTICS.md). Обновить обе платы, проверить `CRC on` при старте, до приёма — `rssi=N/A snr=N/A`, затем отправку A→B и B→A. Проверить один отчёт на нажатие KEY, отсутствие повторов при удержании, очередной отчёт после отпускания/нажатия, сброс счётчиков после RST. Пользователь 6 ноября 2026 подтвердил работу обмена и диагностики; численный отчёт потерь/RSSI/SNR отдельно не предоставлен. Новые изменения проверять отдельно.

## Автоматическая серия между двумя платами

В VS Code запустить **Test radio link**, подробности — [LINK_TEST.md](LINK_TEST.md). Для этой задачи обе платы должны работать на Radio, COM-порты должны быть свободны. Общий `tools/test.py` запускает только модели в памяти; реальное подключение/передача выполняются отдельно по запросу пользователя. Preview помечает данные как симуляцию и не подтверждает радио.

## Адресная версия PN/v1

Обновить обе платы одним новым Radio HEX. План в [ADDRESSED_PROTOCOL.md](ADDRESSED_PROTOCOL.md): INFO/авто-ID, broadcast, unicast, фильтрация чужого назначения, KEY и сброс. PC-тест требует эту прошивку и временно меняет назначения только в RAM. Native модели не подтверждают аппаратный результат; реальный тест запускать отдельно по запросу пользователя.

## Восстановление

В `reference/hal-radio.hex` сохранён предыдущий Radio HEX, в `reference/BASELINE.md` — его контрольная сумма и исходный Git commit. Его можно записать тем же `tools/flash.ps1`, явно передав путь к HEX. При установке новой структуры исходные каталоги рабочего проекта переносятся в `build/migration-backups`; `.git` сохраняется.
