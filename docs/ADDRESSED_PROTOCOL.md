# Адресные пакеты PN/v1

Слой поверх работающего SX1262: адрес отправителя, адрес получателя, метка сеанса и номер пакета. ACK, автоматических повторов, маршрутизации, шифрования и mesh нет. Частота/модуляция/мощность/CRC/распиновка сохранены. **Обе платы нужно обновить одним новым Radio HEX**: прежняя прошивка передавала необрамлённые данные и несовместима с PN/v1.

## Быстрый запуск

1. Собрать Radio и прошить обе платы привычным способом. CMake HEX: `build/Radio/dx_lr30_pj26.hex`; EIDE HEX: `build/eide/Radio/dx_lr30_pj26.hex`.
2. Открыть HTerm на 9600 8N1, local echo выключен. При старте появится строка `[node]` с ID, назначением `dst=FFFFFFFF` и `mtu=234`. По умолчанию вводимый текст передаётся всем узлам.
3. Для запроса актуальных настроек отправить одной операцией `!PJ26 INFO`. Команда должна целиком попасть в один UART-пакет, без пауз больше 5 мс между символами. CR/LF в конце допустимы. В HTerm вводить полную строку в поле отправки, затем отправлять, а не посылать отдельные символы в реальном времени.
4. Узнать ID второй платы, например `A1B2C3D4`. На первой отправить `!PJ26 TO A1B2C3D4`. Последующие данные предназначены только узлу с этим ID.
5. На второй аналогично задать ID первой. Текст, в том числе двоичные payload, на принимающем UART выходит без сетевого заголовка.
6. Для возврата к широковещательной передаче отправить `!PJ26 TO FFFFFFFF`. RST возвращает исходный ID из UID и broadcast-назначение, сбрасывает счётчики и дубликаты.

По-прежнему используется один HEX для всех плат. **ID не нужно вписывать в исходники и пересобирать отдельно для каждой платы.**

## Локальные UART-команды

Команды распознаются только при вводе в локальный UART. Текст принятого радиопакета никогда не выполняется как команда. Это локальная настройка приложения STM32, не AT-интерфейс модуля SX1262.

| Команда | Действие |
|---|---|
| `!PJ26 INFO` | Вернуть настройки, MTU и часть сетевых счётчиков |
| `!PJ26 TO A1B2C3D4` | Задать адрес последующих передач, восемь шестнадцатеричных цифр |
| `!PJ26 TO FFFFFFFF` | Широковещательная передача |
| `!PJ26 ID 00000001` | Временно изменить собственный ID, например для стенда или устранения совпадения ID |
| `!PJ26 RAW` | Следующий один UART-пакет передать как данные, даже если он начинается с `!PJ26 ` |

`00000000` запрещён и как ID, и как адрес назначения; `FFFFFFFF` разрешён только как назначение. Команды и имена операций регистрозависимы, hex-цифры допускают оба регистра. Неправильная команда получает `status=ERROR` и не уходит в радио. Изменения только в RAM, запись Flash/option bytes не выполняется. Для сохранения произвольного ID/назначения между отключениями отдельного механизма пока нет.

Префикс `!PJ26 ` зарезервирован во входном UART-пакете. Чтобы передать такой payload буквально, сначала отдельной отправкой выполнить `!PJ26 RAW`, дождаться ответа, затем отправить нужные байты (до 234). RAW действует ровно на один пакет; INFO после RAW тоже будет этим пакетом данных. Для отмены можно отправить один пакет или перезапустить плату. Обычные бинарные пакеты без этого префикса не требуют экранирования.

Любая команда может дополнительно содержать последний аргумент из восьми hex-цифр — request token. Например `!PJ26 INFO 1234ABCD`. Ответ начинается с `[node] req=1234ABCD status=OK ...`. PC-тест использует случайные tokens, чтобы не принять старую строку за ответ на новый запрос. При ручном вводе token можно опустить (`req=00000000`).

## Идентификаторы и сеанс

ID по умолчанию — 32-битный FNV-1a от 12 байтов заводского UID STM32 (три 32-битных слова, little-endian). Это стабильный удобный адрес, **не гарантия глобальной уникальности и не аутентификация**. Совпадение хешей возможно; PC-тест запрещает одинаковые ID у двух выбранных плат. При необходимости задать разным платам разные ID через локальную команду.

`session`/`boot` — ненулевая 32-битная служебная метка. Начальное значение устанавливается при запуске, рабочее значение один раз уточняется при первом локальном UART-пакете по UID-производному ID и отсчётам существующих SysTick/TIM2, включая момент первого байта UART. После этого оно неизменно до сброса. Стартовая строка до первого ввода может показывать предварительную метку; INFO возвращает рабочую. Это **не аппаратный RNG и не криптографический nonce**, уникальность после всех возможных перезапусков не гарантируется.

Номер начинается с 1 и увеличивается при подготовке каждого пакета. После UINT32_MAX происходит определённое переполнение к 0. Метка сеанса помогает не смешивать номера после обычного перезапуска, ограниченный кэш/TTL также ограничивает время хранения старых номеров. ID/номера не защищают от подмены и злонамеренного replay.

## Формат в эфире

Многобайтовые числа кодируются **little-endian**, по байтам, без отправки C-структур напрямую. SX1262 payload состоит из 21-байтового заголовка и 1..234 байт данных:

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 2 | Magic `50 4E` (`PN`) |
| 2 | 1 | Version = `01` |
| 3 | 1 | Type = `01` (DATA); другие типы пока отвергаются |
| 4 | 1 | Длина полезных данных, 1..234 |
| 5 | 4 | Source ID |
| 9 | 4 | Destination ID или `FFFFFFFF` |
| 13 | 4 | Session tag, ненулевой |
| 17 | 4 | Sequence number |
| 21 | 1..234 | Пользовательские данные |

Отдельного сетевого CRC нет: весь заголовок и данные защищены включённым обязательным LoRa CRC. Сначала драйвер радио проверяет IRQ ошибок/наличие CRC, затем приложение проверяет PN magic, версию, тип, точное совпадение длины, корректность адресов и сеанса. Прежние raw-пакеты и неизвестные версии отбрасываются.

В Radio UART-пакетирование автоматически разделяет поток при 234 байтах либо после 5 мс тишины. Поэтому ввод 255 байт превращается в два payload: 234 и 21, а не обрезается. UART-only echo сохраняет прежний предел 255 байт и не использует сетевые команды/пакеты.

## Приём и дубликаты

1. Невалидный заголовок — `invalid`, без UART-вывода.
2. Source совпадает с собственным ID — `self`, без доставки; это может указывать на совпадение ID/возврат собственного пакета.
3. Destination не свой и не broadcast — `foreign`, без доставки.
4. Для своего/broadcast пакета проверить `(source, session, sequence)` по кэшу.
5. Дубликат — `duplicate`, без доставки. Новый пакет записать в кэш и выдать только payload в UART.

Кэш ограничен **32 последними принятыми пакетами** и **60 секундами** с первого приёма каждого. Возвращённый дубликат не продлевает TTL. Переполнение 32-битного счётчика миллисекунд учтено. Пакеты не по порядку принимаются, если такого ключа ещё нет. Чужие/невалидные пакеты не занимают кэш. После вытеснения записи или истечения TTL такой пакет может быть доставлен снова — это ограниченная защита от обычных дублей, не постоянная база доставки и не защита от атак.

## Диагностика

KEY выводит прежние `[diag]` строки радиочипа, затем `[net]`:

- `id`, `dst`, `boot`, `next`, `mtu` — собственный адрес, назначение, метка, следующий номер и полезная нагрузка.
- `prepared`, `tx_bytes` — подготовленные сетевые пакеты/байты; факт аппаратного TX_DONE отражается отдельно в radio `tx_done`. Это не ACK доставки.
- `accepted`, `rx_bytes`, `broadcast` — доставленные приложению пакеты/байты и число broadcast среди них.
- `foreign`, `duplicate`, `invalid`, `self` — причины отбрасывания.
- `last_tx_valid` и поля `src/dst/seq/boot` — последний подготовленный заголовок.
- `last_seen_valid`, `kind` и поля заголовка — последний валидный сетевой заголовок, включая отброшенный. `kind`: 0 accepted, 1 foreign, 2 duplicate, 3 self. Невалидный заголовок увеличивает invalid, не заменяя last_seen.

Радио `rx_ok` считает все корректные RF-пакеты, в том числе сетевые foreign/duplicate. Поэтому оно может быть больше network `accepted`. Это различие само по себе не означает потерю. Печать по KEY блокирует основной цикл на время UART-вывода, поэтому диагностировать между сериями.

## PC-тест

Задача **Test radio link** и ручной выбор портов сохранены. Теперь перед серией тест:

1. Запрашивает INFO обоих узлов, проверяет разные ID, версию и MTU.
2. Временно задаёт A постороннее назначение и отправляет один пробный пакет.
3. Требует отсутствия этого payload в UART B **и** увеличения `foreign` на B с совпадающими source/destination/sequence и `last_kind=1`. Простое отсутствие данных из-за потери RF не даёт ложного успеха.
4. Направляет A на B, B на A и запускает прежнюю серию проверки байтов/потерь/задержек.
5. В finally пытается вернуть исходные назначения и освобождает COM-порты. При обрыве связи/принудительном завершении восстановление не гарантируется; RST возвращает broadcast.

JSON содержит исходные NodeA/NodeB, Addressing с доказательством фильтрации и статистику основной серии. Дополнительный отвергнутый пакет в основной Sent/Received серии не входит, но увеличивает аппаратные/сетевые счётчики на платах — ожидается минимум один foreign на B. Максимум `-Size` для реальной адресной прошивки **234**, стандартные 64 подходят. Preview не обращается к узлам и не подтверждает проверку аппаратной адресации.

## Программные проверки и границы

`test_network` выполняет настоящие network/node_console/serial_frames на ПК: независимый wire-vector, длины/версии/типы, бинарный MTU, unicast A↔B, broadcast на два получателя, чужие/self/невалидные пакеты, дубли/сеанс/TTL/вытеснение/переполнения, локальные команды/RAW, ограниченные отчёты и разделение 255→234+21.

`test-link-host.ps1` проверяет корреляцию/дробление INFO, отсутствие fallback на старую прошивку и защиту адресного probe от ложного успеха при потере/чужом событии. Общие проверки запускаются `python tools/test.py`, без открытия COM.

Новая адресная версия требует отдельной проверки на двух обновлённых платах. Успех предыдущего CRC/diagnostics/link-test варианта на неё автоматически не переносится. Проверить broadcast, unicast, смену назначения, RST и PC-тест, затем при необходимости записать аппаратный результат. Автоматической прошивки и запуска RF-теста агентом при разработке не выполняется.
