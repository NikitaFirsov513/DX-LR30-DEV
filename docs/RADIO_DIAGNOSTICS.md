# CRC и диагностика Radio

Изменения после `V-0.1.0`: обязательный CRC LoRa и локальная статистика по KEY. Частота, SF/BW/CR, мощность, распиновка и формат пользовательских данных сохранены. Одна прошивка Radio работает на обеих платах; обновить обе. UART-only echo остаётся прежним.

## Сборка и проверка на платах

1. Собрать Radio кнопкой EIDE Build или `python tools/build.py --target Radio`. EIDE пишет HEX в `build/eide/Radio`, CMake — в `build/Radio`.
2. Закрыть терминалы, прошить обе платы новым Radio HEX штатной задачей Flash. При двух подключённых платах явно выбрать порт через `-OverridePort COMx`. Для перехода на другую плату менять порт, а не target.
3. Открыть HTerm для каждой платы: 9600 8N1, local echo выключен. После RST стартовая строка должна содержать `CRC on`.
4. До первого радиоприёма нажать KEY: ожидаются нулевые счётчики и `rssi=N/A snr=N/A`. KEY — пользовательская кнопка PB12, не RST. Нажатие держать хотя бы 30 мс.
5. Отправить один короткий пакет A→B, дождаться его появления на B, затем нажать KEY на обеих платах. На A ожидаются `tx_started=1`, `tx_done=1`; на B — `rx_ok=1`, фактическое число принятых байтов, RSSI/SNR. В HTerm отправлять строку целиком одной операцией, без автоматических повторов и неожиданных CR/LF.
6. Повторить B→A. До отправки новой серии дождаться окончания диагностического вывода. Одно нажатие даёт один отчёт; удержание не повторяет его. Нажатие во время TX запоминается и обслуживается после возврата радио в RX.
7. Проверить пакеты 1/255 байт и короткий→длинный→короткий, затем RST и повторный обмен. После сброса счётчики нулевые, RSSI/SNR снова `N/A` до первого корректного приёма.

Пример после одной отправки и одного приёма трёхбайтового пакета (значения RSSI/SNR здесь иллюстративные):

```text
[diag] state=RX uptime_ms=12345
[diag] tx_started=1 tx_done=1 tx_bytes=3 rx_ok=1 rx_bytes=3
[diag] crc_err=0 header_err=0 no_crc=0 tx_timeout=0 rx_timeout=0 watchdog=0 radio_err=0
[diag] uart_err=0 uart_drop=0 rssi=-100 dBm snr=-8 dB
```

## Поля отчёта

| Поле | Значение |
|---|---|
| `state`, `uptime_ms` | Состояние радио и время с момента запуска MCU; время переполняется примерно через 49,7 дня |
| `tx_started` | Успешно запущенные передачи; отказ SPI до запуска сюда не входит |
| `tx_done`, `tx_bytes` | Локальные TX_DONE и байты этих передач; это не ACK получателя |
| `rx_ok`, `rx_bytes` | Пакеты/байты, принятые без ошибок заголовка/CRC, с обязательным CRC и переданные приложению |
| `crc_err`, `header_err` | Обработанные радио IRQ ошибок CRC и заголовка; один IRQ может содержать обе ошибки |
| `no_crc` | Полученные пакеты с выключенным CRC в explicit header; payload отбрасывается |
| `tx_timeout`, `rx_timeout` | Обработанные IRQ TIMEOUT в соответствующем состоянии |
| `watchdog` | Восстановление после отсутствия события завершения TX за 6500 мс; успех передачи не засчитывается |
| `radio_err` | Ошибки операций драйвера/транспорта, переводящие радио в FAULT |
| `uart_err` | События ошибок USART: framing/noise/parity/overrun |
| `uart_drop` | UART-пакеты, отброшенные из-за переполнения очереди или события ошибки USART |
| `rssi`, `snr` | Целочисленные dBm/dB драйвера Semtech для последнего корректного пакета; могут быть отрицательными, до первого пакета — `N/A` |

Все счётчики 32-битные, накапливаются до сброса MCU, переполняются по модулю 2^32. Повторная инициализация радиочипа не обнуляет их. Пакет с ошибкой не заменяет RSSI/SNR последнего корректного пакета. При фатальной ошибке приложение пытается вывести один снимок перед остановкой; при неисправном UART его получение не гарантируется.

## CRC и совместимость

`RADIO_CRC_ENABLED=true` включает CRC LoRa в TX/RX. В explicit-header режиме информация о наличии CRC приходит также из заголовка отправителя. Поэтому один только параметр приёмника не даёт основания считать каждый принятый пакет проверенным: код читает заголовок через штатный Semtech API и отбрасывает `CRC off` независимо от отсутствия IRQ CRC_ERROR. Из UART CRC не виден, размер пользовательского пакета остаётся до 255 байт. Базовая `V-0.1.0` передаёт без CRC: обновить обе платы.

## Ограничения измерений

Отчёт печатается только по KEY либо при фатальной ошибке, не передаётся по радио и не резервирует какие-либо команды/байты в UART-вводе. Он вставляет локальные `[diag]` строки в общий UART-вывод. При 9600 бод печать занимает несколько сотен миллисекунд и в это время задерживает обработку радиособытий; не запрашивать статистику посреди потока для измерения потерь.

Снимать показания до и после серии с номерами сообщений и интервалом, достаточным для airtime LoRa. Сравнивать `tx_done` отправителя и `rx_ok` получателя при отсутствии посторонних передач, а данные проверять по номерам/содержимому на ПК. Это ещё не автоматический измеритель потерь: пакеты, которые радио вовсе не обнаружило, не увеличивают `crc_err`; нет адресов, sequence number, ACK и повторов. Одновременная передача двух плат может приводить к коллизиям.

Новые CRC/диагностика проверяются программными тестами; аппаратный результат для них нужно записать отдельно после прошивки обеих плат.
